# 1. Planning
## Repository responsibilities
- Repository onboarding guidance (policies, scope, admissible data)
- Provision of DMP templates and examples for sensitive data
- Risk classification framework and curation pathways (incl. escalation)
- AAI integration options and access‑policy patterns
- Legal and policy toolkit (licensing, DUA/DTA templates, publication policies)
- Readiness of secure environments (TRE‑like zones, logging, audits)
- Supported PIDs, metadata profiles, vocabularies, and interoperability targets

# 2. Collection
## Repository responsibilities
- Ingestion interfaces and pipelines; API endpoints; assisted deposit
- Curatorial review (factual accuracy, ethical/legal conformity, consent checks)
- Validation services (schema, format, completeness) and feedback to depositors
- Sensitive metadata handling rules (visibility tiers, redaction patterns)
- Registration of local entities (projects, cohorts) and resolver services

# 3. Processing
## Repository responsibilities
- Provisioning/brokering of secure processing environments (TRE/VDI/containers)
- Managed workflow services (CWL/Snakemake/Nextflow) and provenance capture
- Reference vocabularies and semantic services; mapping aids and validators
- Interim storage and quarantine areas with policy‑driven movement
- Audit logging, change tracking, and approvals

# 4. Analysis
## Repository responsibilities
- Managed computation close to data, with controlled egress rules
- Versioned storage of code, containers, and notebooks; binding to datasets/PIDs
- Run registries / workflow execution records and provenance graph services

# 5. Preservation
## Repository responsibilities
- Registration in repository (DOI/other PID assignment; catalogue entry)
- Long‑term archiving; replication and integrity monitoring
- Versioning and change logging; tombstone and retraction procedures
- Preservation planning (format migration paths; designated community statement)

# 6. Sharing / Publication
## Repository responsibilities
- Access control enforcement via AAI (role/attribute/purpose‑based models)
- Access monitoring, usage analytics, and full audit trail
- Machine‑actionable licences/rights statements and policy exposure
- Quality badges/FAIR assessments; citation guidance in the landing page

# 7. Reuse
## Repository responsibilities
- Citation according to FAIR principles (persistent identifiers; CFF/RO‑Crate support)
- Integration into external systems (harvest to NMA/NKR, indexing, resolvers)
- Provenance trail for traceability; dataset–software–publication linkages
- Reuse monitoring and impact metrics

# 8. Cross‑Cutting Controls and Enablers
- Security standards and controls (ISO 27001 aligned; risk‑based controls; logging)
- Ethics and legal compliance (GDPR/IP/EHDS/DGA/DA) and governance
- AAI and policy models (authentication, authorisation, purpose limitation)
- Provenance, identifiers, and metadata quality management
- QA/QC framework (entry checks, curation checks, publication checks)
- Vendor lock‑in avoidance and data portability (open formats, APIs, export)

# 9. Domain‑ and Repository‑Specific Provisions
- Domain addenda (metadata profiles, terminologies, specific risks)
- Repository‑specific policies and submission guidelines

# 10. Training and Support
- Training catalogue (curators, admins; webinar recordings)
- Documentation and user guides (tools, services, repositories)
- Communication channels (helpdesk, AI assistant)

# 11. Sustainability and Governance of the Methodology
- Review and update cycle; change management; versioning
- Roadmap and alignment with NDI/NRP services
- Contact information

# 12. Role‑Based Interactive Checklists
- Repository administrators and curators
- (Optional) Data stewards, ethics committees, infrastructure operators

# 13. Templates and Exemplars
- DMP (sensitive data), SAP, consent language, DUA/DTA, access policy
- README, metadata exemplars, workflow and provenance records
